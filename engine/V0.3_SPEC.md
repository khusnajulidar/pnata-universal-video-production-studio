# Production Engine v0.3 — Specification (Draft for Implementation)

**Status:** Specification approved for planning; implementation not started  
**Target branch:** `feat/production-engine-v0.1.0`  
**Baseline:** v0.1 still renderer and v0.2 animated 2D renderer  
**Compatibility rule:** v0.1 and v0.2 projects and commands remain supported; v0.3 is a new explicit render path.

## 1. Purpose

v0.3 should turn the proven v0.2 animated 2D compositor into a more dependable production renderer for typography-led motion graphics, explainers, educational sequences, visual essays, and other projects whose visual language fits a 2D layer compositor.

The release focuses on three practical gaps:
1. Reliable text and image layout rather than merely drawing within fixed boxes.
2. A real timeline model for layer visibility and timed captions.
3. A controlled audio stage for reviewed narration, genuinely non-musical sound effects, and genuinely non-musical natural/environmental ambience.

This is not a claim that the engine becomes a full nonlinear editor or a universal renderer for every production profile. Backend capability detection remains mandatory.

## 2. Non-negotiable P'Nata policy

These rules are hard validation gates, not optional creative preferences:
- **No music, without exception:** no songs, instruments, soundtrack, score, beat, rhythm track, melodic bed, musical loops, generative music, or music-like ambience.
- Allowed audio only: speech/narration, genuinely non-musical sound effects, genuinely non-musical natural/environmental ambience, or silence.
- Audio must be supplied as separate, explicitly typed assets. Reject unknown/unclassified audio and any track typed as music. Never extract or silently pass embedded audio from media assets.
- No complete depictions of humans or animals, including silhouettes or fragments arranged to imply a complete figure. Prefer non-figurative objects, architecture, nature, typography, geometry, and abstract visuals.
- No figurative depiction of Allah, prophets, angels, or unseen matters.
- Human review declarations are workflow attestations, not machine certification. The final rendered output still requires human review.
- If a policy status is missing, ambiguous, or failed, rendering must stop rather than guess.

## 3. v0.3 goals

### Must deliver
- Text layout: wrapping, alignment, line spacing, padding, vertical alignment, font fallback, and explicit overflow behavior.
- Image layout: `contain`, `cover`, and `stretch` fit modes with deterministic crop/anchor behavior.
- Timeline timing: layer start/end, trim/offset semantics, and timed caption/text layers while retaining scene sequencing.
- Audio composition: explicit narration/SFX/ambience tracks, trim, offset, gain, fades, and deterministic mix.
- Technical QC: stream inventory, duration/frame-rate/dimensions, audio presence/absence, audio peak/clipping checks where supported, and machine-readable report.
- Capability declarations and clear unsupported-feature errors.
- Automated tests plus at least one reproducible silent render fixture and one reviewed-audio fixture (speech/SFX/ambience only).

### Quality goals
- Deterministic renders for the same project, assets, fonts, backend versions, and settings.
- Helpful validation errors with file path and field context.
- Preserve readable typography at the target canvas size; no silent clipping or unexpected text shrink.
- No silent fallback when a requested feature is unsupported.

## 4. Proposed architecture

Keep the v0.2 renderer intact. Add a separate v0.3 path with narrowly scoped modules:

- `scene_v3.py`: v0.3 project loading, schema validation, policy validation, timing validation, and asset provenance checks.
- `layout_v3.py`: text measurement/wrapping, alignment, overflow policies, font resolution, and image fit/crop geometry.
- `render_v3.py`: deterministic frame compositor using the shared low-level primitives where safe; scene and layer timeline evaluation.
- `audio_v3.py`: explicit allowed-track validation, trim/offset/fade/gain, and FFmpeg mixing.
- `qc_v3.py`: FFprobe-based video/audio stream checks and machine-readable QC.
- `render_v3_cli.py`: command-line interface.
- `schema/scene-project-v0.3.schema.json`: machine-readable project schema.
- `examples/v03-typography/` and `examples/v03-reviewed-audio/`: fixtures.
- `tests/test_scene_v3.py`, `tests/test_layout_v3.py`, `tests/test_render_v3.py`, `tests/test_audio_v3.py`, `tests/test_qc_v3.py`.

Do not refactor v0.1/v0.2 as a prerequisite. Share code only after tests prove that reuse does not change existing behavior.

## 5. Project and timeline model

A v0.3 project declares:
- project identity and version;
- canvas width/height, FPS, total duration, background, output encoding settings;
- mandatory policy declarations;
- scenes in editorial order;
- assets with path, media type, provenance/source note, rights status, and review status;
- explicit video layers, timed text/caption layers, and audio tracks.

Scene durations define the master editorial timeline. A visual layer may declare:
- `start` and `end` in seconds relative to its scene;
- `in_point` for source assets where applicable;
- normalized anchor position and anchor point;
- transform keyframes;
- opacity and rotation;
- explicit z-order (array order may remain the default);
- optional enter/exit behavior only from the supported transition list.

Validation must reject negative durations, end-before-start, invalid source ranges, out-of-range keyframes, undefined assets, and timeline gaps/overlaps when the project explicitly requires contiguous coverage.

## 6. Typography and layout

Text layers must support:
- font family/path resolution with declared fallback order;
- font size, weight/style where the selected font supports them;
- horizontal alignment: left, center, right;
- vertical alignment: top, middle, bottom;
- wrapping within a defined box;
- line spacing and inner padding;
- fill and optional stroke;
- explicit overflow policy: `error`, `clip`, or `shrink_to_fit`.

Default overflow policy should be `error`; never silently crop or shrink text. `shrink_to_fit` must have a declared minimum font size. If the text still does not fit, fail validation/render.

Image layers must support:
- `contain`: preserve all source pixels inside the box;
- `cover`: fill the box and crop deterministically;
- `stretch`: distort only when explicitly requested;
- crop anchor/position and optional opacity/transform.

The engine must not infer that an image is policy-compliant. Every imported image still requires its own review declaration and provenance entry.

## 7. Audio model and safety gates

Each audio track must have exactly one allowed category:
- `narration`
- `sfx`
- `natural_ambience`

Each track requires:
- asset path and provenance;
- explicit human declaration that it is not music and is suitable for its category;
- source in-point, timeline start, duration/trim;
- gain;
- optional fade-in/fade-out;
- optional channel handling that is supported and documented.

Reject:
- `music`, `score`, `soundtrack`, `beat`, `instrumental`, unknown categories, or missing category;
- any audio asset without explicit review;
- embedded audio in visual media or untyped audio sidecars;
- attempts to loop audio unless a future specification explicitly supports a reviewed non-musical environmental loop.

The mixer must not generate, compose, synthesize, or recommend music. It only places and mixes user-supplied, reviewed allowed audio. Silence remains a valid and preferred output when no reviewed audio is supplied.

Audio QC should report stream presence, duration, sample rate, channels, peak level and clipping where the installed FFmpeg/FFprobe filters support reliable measurement. If a metric is unavailable, report `NOT_AVAILABLE`, not a fabricated value. Do not claim semantic music detection; that remains human review.

## 8. Captions and subtitles

v0.3 should support timed text/caption layers in the project timeline. Basic SRT import may be included only if it can be implemented and tested without compromising the core renderer. Caption timing, safe margins, wrapping, and readability must be validated. Automatic speech recognition and automatic translation are out of scope.

## 9. CLI proposal

New command only:
```bash
pnata-render-v3 path/to/project.json -o dist/output.mp4 --qc dist/qc.json
```

Optional diagnostic command:
```bash
pnata-validate-v3 path/to/project.json
```

The CLI must fail with a non-zero exit code for invalid schema, policy violations, missing assets, unsupported capabilities, render failures, or required QC failures.

## 10. QC and acceptance gates

A v0.3 release candidate is not accepted until all are true:
1. Existing v0.1 and v0.2 tests continue to pass unchanged.
2. v0.3 schema and policy validation tests pass.
3. Typography fixtures prove wrapping, alignment, fallback, and overflow behavior.
4. Image fixtures prove contain/cover/stretch and crop anchor behavior.
5. Timeline fixtures prove visibility windows, keyframes, captions, and scene boundaries.
6. Audio tests prove narration/SFX/natural ambience mixing, timing, fades, gain, silence output, and rejection of music/unclassified/unreviewed assets.
7. FFprobe confirms expected video/audio streams, dimensions, FPS, duration, and codec.
8. QC reports unavailable metrics honestly.
9. Human visual review confirms no unintended clipping, blank frames, flicker, or policy violations.
10. Human audio review confirms every audible asset is allowed and no music is present.
11. Delivery includes source project, asset manifest/provenance, MP4, QC report, and README when those artifacts are actually generated.

## 11. Explicitly out of scope for v0.3

- Full nonlinear editing of arbitrary camera footage.
- 3D rendering, camera/lens simulation, advanced lighting, particle simulation, complex masks, and vector path animation.
- Automatic image understanding or machine certification of the living-being policy.
- Semantic music detection or automatic certification that an audio file contains no music.
- Automatic rights/copyright clearance.
- TTS, ASR, translation, or generative audio unless separately specified, capability-tested, and policy-reviewed.
- Cloud rendering, collaboration, GUI editor, and plugin marketplace.
- Automatic visual storytelling decisions that replace the Creative Director/profile workflow.

These capabilities may be considered in later releases or delegated to a verified specialist backend.

## 12. Implementation sequence

**Milestone A — schema and validation**
- Define schema and project loader.
- Add strict policy, asset, timeline, and capability validation.
- Add negative tests first.

**Milestone B — typography and image layout**
- Implement measurable text wrapping and overflow.
- Implement deterministic image fit/crop.
- Render reference fixtures and inspect output.

**Milestone C — timeline and captions**
- Add layer visibility windows and timed caption support.
- Verify keyframes and scene transitions remain deterministic.

**Milestone D — reviewed audio**
- Implement explicit allowed audio categories and track mixer.
- Add rejection tests for music, unknown types, unreviewed files, and embedded audio.
- Verify silence and allowed-audio outputs.

**Milestone E — QC, docs, and release gate**
- Add FFprobe/audio QC.
- Run full regression suite on Python 3.11 and supported Windows/Linux environments.
- Record actual test results; do not mark features complete before execution and review.

## 13. Versioning and status discipline

- v0.3 is a new renderer and schema, not a silent mutation of v0.2.
- Keep the current development branch; do not merge to `main` without explicit authorization.
- This document is a design specification only. No v0.3 implementation, tests, or runtime capability is claimed by its presence.
- Update this specification when implementation reveals a necessary design change, and record the reason.

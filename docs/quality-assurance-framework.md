# P'Nata Quality Assurance Framework

## Principle
The best version is the best justified version for the brief—not the most effects, fastest render, or highest resolution.

## Three review passes
### Editorial / substance
Audience and outcome are clear; message is accurate; claims, quotations, religious references, translations, and attributions verified; each scene advances the story; caveats preserved.

### Craft / experience
Visual language fits selected profile; composition, hierarchy, typography, motion, cinematography, lighting, colour, and pacing are intentional; sound is clear and restrained with no music; target viewing size is checked; effects are motivated.

### Technical / compliance / delivery
Correct dimensions, frame rate, codec, duration, aspect ratio, audio layout, and file integrity. No unintended black/frozen frames, flash frames, clipping, dropped audio, or sync drift. Check captions, safe areas, contrast, rights, P'Nata policy, source files, and handover package.

## Mandatory fail conditions
Music; complete human/animal depiction; unsupported factual/religious claims; unlicensed assets; materially misleading editing; broken/incorrect audio; corrupt delivery.

## Review loop
Render proxy → inspect entire piece → log defects with timecode/severity/evidence → fix source → render again → rerun affected checks → full final playback and probe → report pass/fail/not checked separately.

## Defect severity
Blocker: policy, factual, rights, file-integrity failure.
Major: comprehension, story, sync, readability, continuity failure.
Minor: polish issue not blocking comprehension or compliance.

## QC report
Include profile(s), target tier, render settings, tool versions, sources/rights, review date, known limitations, and file hash when available. Never convert NOT CHECKED into PASS.
